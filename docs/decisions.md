# Decisions

Decisions made after the planning phase (ENG-011). D-01 to D-29 are in the PRD's Appendix A, including D-24 to D-29,
which were added there before this file existed. New decisions continue from D-30. IDs are never reused; to reverse
a decision, add a new one that supersedes it.

| D-41 | 2026-11-02 | **The path guard takes its configuration as an input, built from a home root.** The configuration holds the home root, the allowed roots and the protected locations (section 8.4); home-relative entries such as `~/.ssh` are derived from the home root. The app builds the one production configuration in a single place, from the real home folder and the full list. Tests build theirs the same way from the fixture root as home, with one difference only: the system list drops the `/private` prefix that contains the temporary folder (`/var` resolves to `/private/var`). Every other system location (`/System`, `/usr`, `/Library`, …) stays protected in tests. A test asserts that the production configuration rejects a path in the temporary folder, so weakening the real rules fails CI. | The fixture root lives in the temporary folder, which resolves to `/private/var/folders/…`; rule SAF-007 (d) would reject every fixture path, leaving the guard and everything behind it untestable. The exemption is explicit, minimal and pinned by a test, and the shipped guard is not weakened. Owner decision, 2026-11-02. | A fixture root under the real home folder (breaks SAF-016 and AGENTS.md safety rule 4); a separate test volume (rejected by SAF-007 (e)); a test-only switch that turns protected-location checks off |
| D-42 | 2026-11-02 | **The fixture-root harness is a `FixtureRoot` class in `ShuckKitTestSupport`.** Each instance creates `ShuckFixtures/<UUID>` in the temporary folder, reports its path with symlinks resolved (`realpath`, so `/private/var/…`), and removes it when released, after restoring access to folders a test made unreadable. Paths are given relative to the root; `..`, absolute paths and `~` are rejected, and every path is checked to be inside the root after resolving symlinks, so a symlink out of the root or a dangling one is refused. The file factory never overwrites and writes real bytes, so allocated size matches. Failures throw `FixtureError` instead of recording a test issue. | One object per test, with no shared state, suits Swift Testing's parallel tests. Throwing works in both Swift Testing and XCTest, so UI tests can use the harness (M1-T15). `URL.resolvingSymlinksInPath()` strips `/private` from temporary paths, so it would disagree with the path guard (D-41). | A shared fixture folder cleaned between tests; `URL.resolvingSymlinksInPath()`; recording issues through the Testing module, which XCTest cannot use |
| D-43 | 2026-11-02 | **Path guard design (M1-T02).** Allowed roots are passed with each check, by the tool or sub-tool that owns the target; the configuration holds the home folder and the protected locations (refines D-41). Checks run in the order (a), (b), (e), (d), (c). Paths are compared component by component after resolving symlinks with `realpath`. A target that is itself a symlink must pass as the link and as its destination, and the guard returns the link, so the executor acts on the link, never on what it points to; a dangling symlink is rejected. A target that contains a protected location (for example `~/Library`) is rejected too. Protected bundles are matched by extension wherever they are (`photoslibrary`, `photolibrary`, `musiclibrary`, `tvlibrary`, `backupbundle`) and by the name `Backups.backupdb`; Music and TV libraries are also protected in their default folders. "Other credential folders" (section 8.4) are `~/.azure`, `~/.docker`, `~/.netrc`, `~/.password-store` and `~/.config/gcloud`. Rule (e) checks that the deepest existing part of the path is on the root file system. Rules (a) and (d) compare names with case folded, as the default case-insensitive APFS volume does; rule (c) stays case-sensitive, so a mismatch can only reject. | SAF-007 (c) says the root belongs to the tool or sub-tool, and the registry that knows them arrives in M1-T06. Checking both link and destination is the stricter reading of "a symlink pointing outside the root"; acting on the link is how the Trash treats symlinks anyway. `URL.resolvingSymlinksInPath()` and `URL.standardizedFileURL` both strip `/private`, which would hide the temporary folder from the D-41 test. `/dev` is a separate file system on every Mac, so tests use it for (e). `realpath` fixes the case of existing parent folders but not of the last component or of paths that don't exist yet, so `~/.SSH` passed (d) before folding (found by code scanning on pull request #3). | Allowed roots stored in the configuration (one set for every tool); resolving a final symlink and acting on its destination; accepting dangling symlinks; `volumeIdentifierKey` comparison (reports the same as the root check on the owner's Mac, with more code) |
| D-44 | 2026-11-02 | **The 80% engine coverage gate (SM-4) counts `ShuckKit` and `ShuckExecution` only.** `scripts/test.sh` still lists `ShuckKitTestSupport` in the report, marked "not gated", and fails when the gated total is below 80% or when no engine code is found. Supersedes the report-only part of D-32. Owner decision, 2026-11-02. | Test support is exercised by the tests that use it, not shipped; counting it would inflate the figure. | Counting test support; a per-file gate |
| D-45 | 2026-11-02 | **`ShuckKit/History/` may change the permissions of Shuck's own data folder and log.** A separate static-check rule, `permissions`, bans `setAttributes`, `chmod`, `chown` and their `f`/`l`/`at` variants everywhere outside `ShuckExecution`, except in `History/`. The history log fixes a data folder that is not 0700 and a log file that is not 0600 when it opens (NFR-SEC-005). The `mutation` rule no longer lists these calls; the `permissions` rule now also catches `fchmod` and the other variants, which the old `\bchmod\(` pattern missed. Owner decision, 2026-11-02. | SAF-017 protects user files; Shuck's own log is not one. Refusing to open a log with loose permissions would block every action until the user fixed it by hand. | Refusing to open the log; moving the permission fix into `ShuckExecution`, which `ShuckKit` cannot call (D-28) |
| D-46 | 2026-11-02 | **History log design (M1-T03).** `HistoryLog` is an actor that keeps the log open with `O_APPEND`, writes each record with one `write` call and calls `synchronize()` before returning (HIS-001). It opens with `O_NOFOLLOW` and refuses a data folder or log file that is a symlink. A line cut short by a crash is skipped by the reader, reported by line number, and the writer starts the next record on a new line. Lines from a newer schema version are reported the same way. Timestamps are ISO 8601 UTC with milliseconds. Records are built with `HistoryRecord.intent(...)` and `.result(...)`. Tool IDs are a `ToolID` struct (`LRG`, `OLD`, …) and the tier an enum `Tier`, shared with later tasks. | Reporting unreadable lines keeps "no silent failures" (SAF-011) without losing the readable records. A symlink in Shuck's data folder could redirect writes to another file. Milliseconds keep records from the same second in order. A struct for tool IDs lets a sub-tool declare its ID next to its code (FCL-003). | Failing the whole read on one bad line; seconds-only timestamps; an enum of tool IDs |
| D-47 | 2026-11-02 | **Tests never use the real Trash.** `ShuckExecution` defines a `Trash` protocol; the app uses `SystemTrash` (`FileManager.trashItem`), and tests use a fake that moves items into `.Trash` inside the fixture root, adding a number to a name that is taken. `SystemTrash` is a few lines and has no automated test. Owner decision, 2026-11-02. | `trashItem` on a fixture file moves it into the real `~/.Trash` in the home folder, which breaks SAF-016 and AGENTS.md safety rule 4. | One tightly controlled test against the real Trash |
| D-48 | 2026-11-02 | **Plans and the Trash executor (M1-T04).** A `Plan` is created only if every item's tier allows its method (SAF-004) and the path guard accepts it; it keeps its tool's allowed roots for re-validation. The method enum is `ActionMethod`, because `Method` clashes with the Objective-C runtime type. For each item the executor writes the intent record, re-validates (path guard, then exists, same kind, size within 64 KiB or 1%, whichever is larger), acts, and writes the result record, so skipped items are logged too. It acts on the path the guard returns. If the log cannot be written, the run stops and the remaining items are skipped. Items with another method are skipped without a log record. `ItemSnapshot` (kind and allocated size, folders summed without following symlinks) lives in Scanning so the scanner can reuse it. | Writing the intent first means the log shows every item the run looked at, including the ones it skipped (SAF-011). The size tolerance absorbs small changes such as a Finder `.DS_Store` inside a package, while a file that grew by more than 64 KiB counts as changed. | Re-validating before the intent record (skipped items would leave no trace); an exact size match; a separate `Planning` check outside `Plan`'s initializer |
| D-49 | 2026-11-02 | **Pull requests open as drafts.** When all checks pass and code scanning reports no new alerts, the agent marks the pull request ready for review and turns on auto-merge (squash). Owner decision, 2026-11-02. | Lets the owner see work early while only clean changes reach `main`. | Opening pull requests ready for review; merging by hand after every check |

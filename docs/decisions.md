# Decisions

Decisions made after the planning phase (ENG-011). D-01 to D-29 are in the PRD's Appendix A, including D-24 to D-29,
which were added there before this file existed. New decisions continue from D-30. IDs are never reused; to reverse
a decision, add a new one that supersedes it.

| ID | Date | Decision | Rationale | Rejected alternatives |
|---|---|---|---|---|
| D-30 | 2026-11-02 | **App version starts at 0.0.1.** `MARKETING_VERSION` matches the next milestone tag and is bumped in a pull request before tagging. The About panel shows "Copyright © 2026 Nguyen Thai Binh". | The M0 tag is `v0.0.1` (section 13). The release fails if tag and version differ (D-36). | Xcode's default 1.0; deriving the version from the tag at build time, which leaves source builds without the real version |
| D-31 | 2026-11-02 | **Tests sign ad hoc on CI and use the project's signing locally.** `scripts/test.sh` adds `CODE_SIGN_IDENTITY=-` only when `CI=true`. | CI runners have no certificates. Locally, macOS ties UI-automation permission to the test runner's signature, so an ad hoc runner hangs on an approval prompt. Verified on GitHub on 2026-11-02: UI tests pass on the `xcode-27` runner (Xcode 27.1). | Ad hoc everywhere (breaks local UI tests); importing a development certificate into CI (puts a secret in pull request workflows) |
| D-32 | 2026-11-02 | **Engine coverage is reported, not yet enforced.** `scripts/test.sh` prints per-file line coverage of `Packages/ShuckKit/Sources` from SwiftPM's JSON report. The 80% gate (SM-4) is added when the engine has code. | The engine has no executable lines yet, so a percentage means nothing. Tracked in `docs/progress.md`. | A gate now, which passes vacuously; `llvm-cov report`, which depends on SwiftPM's changing build layout |
| D-33 | 2026-11-02 | **Code style:** swift-format's defaults with 4-space indentation and 120-character lines. The engine's own `.swift-format` also turns on `NeverForceUnwrap`, `NeverUseForceTry` and `NeverUseImplicitlyUnwrappedOptionals`, which apply to its tests too. `as!` in the engine is caught by the static checks, since swift-format has no rule for it. | 4 spaces is Xcode's default, so code written in Xcode stays clean. 120 columns fits SwiftUI modifier chains. The force rules implement AGENTS.md's "no force unwraps in the engine". | 2-space indentation (swift-format's default); the force rules in the app too |
| D-34 | 2026-11-02 | **GitHub Actions:** only GitHub-authored actions (`actions/checkout`, `actions/upload-artifact`), each pinned to a full commit SHA with the version in a comment. CI uploads the `.xcresult` bundle when a run fails. | A tag can be moved; a SHA cannot (R-13). | Version tags such as `@v7`; third-party actions for signing or releases |
| D-35 | 2026-11-02 | **Branch ruleset:** a pull request with 0 required approvals, squash merge only, the "Lint, build and test" check required and up to date, no force pushes, no deletions, no bypass list. | The owner is the only reviewer and GitHub does not let authors approve their own pull requests; the required check is the real gate. | 1 required approval (would block every merge); allowing merge commits |
| D-36 | 2026-11-02 | **Release build:** `scripts/build-dmg.sh` archives with manual Developer ID signing and copies the app out of the archive (no `-exportArchive`). It checks Hardened Runtime is on and `get-task-allow` is absent, then notarizes and staples both the app and the DMG. The build number is the commit count (`git rev-list --count HEAD`). Tags `v0.*` become pre-releases. | Fewer moving parts than an export-options plist; the checks cover NFR-SEC-003 directly. The commit count increases along `main` and is the same locally and on CI. Stapling both lets the app open offline whether or not it is still in the DMG. | `-exportArchive` with `ExportOptions.plist`; the CI run number as the build number (differs locally). Verified by the `v0.0.1` release on 2026-11-02: app and DMG notarized and stapled, Gatekeeper accepts both. |
| D-37 | 2026-11-02 | **Release secrets** live in a GitHub environment named `release`, limited to `v*` tags. Notarization uses an App Store Connect team API key with the Developer role. Locally, `scripts/notarize.sh` falls back to a notarytool keychain profile named `shuck-notary`. The certificate goes into a temporary keychain that is deleted after the job. | Environment secrets cannot reach pull request workflows (ENG-008); Developer is the narrowest role that can notarize (R-13). Verified by the `v0.0.1` release on 2026-11-02. | Repository-level secrets; Apple ID with an app-specific password |
| D-38 | 2026-11-02 | **Static checks are a bash script of pattern rules, with a self-test.** Files may be written only in `ShuckExecution` and in `ShuckKit/Sources/ShuckKit/History/` (Shuck's own log). Tests and test support may print, write fixtures and run shell scripts. Whole-line comments are ignored. | No dependencies, readable by the owner, fast. The self-test (`scripts/static-checks-test.sh`) stops a broken pattern from passing everything silently. A pattern search is a safety net, not a proof. | A Swift-syntax-based checker (much more code for M0); banning all file writes outside Execution (would block the history log) |
| D-39 | 2026-11-02 | **The sidebar is a hard-coded `SidebarItem` enum until the tools registry exists (M1-T06).** The app target keeps Xcode's default main-actor isolation; plain data types there are marked `nonisolated`. | The registry lives in ShuckKit and is M1 work. Main-actor by default suits SwiftUI code. | Building the registry in M0 |
| D-40 | 2026-11-02 | **`swift-tools-version: 6.2` for ShuckKit**, while Xcode 27 ships Swift 6.4. | 6.2 is the oldest version that knows `.macOS(.v26)`, so macOS 26 support (L-02) can still build the engine with Xcode 26 (D-06). | 6.4, which would rule out Xcode 26 |

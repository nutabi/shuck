| D-43 | 2026-11-02 | **Path guard design (M1-T02).** Allowed roots are passed with each check, by the tool or sub-tool that owns the target; the configuration holds the home folder and the protected locations (refines D-41). Checks run in the order (a), (b), (e), (d), (c). Paths are compared component by component after resolving symlinks with `realpath`. A target that is itself a symlink must pass as the link and as its destination, and the guard returns the link, so the executor acts on the link, never on what it points to; a dangling symlink is rejected. A target that contains a protected location (for example `~/Library`) is rejected too. Protected bundles are matched by extension wherever they are (`photoslibrary`, `photolibrary`, `musiclibrary`, `tvlibrary`, `backupbundle`) and by the name `Backups.backupdb`; Music and TV libraries are also protected in their default folders. "Other credential folders" (section 8.4) are `~/.azure`, `~/.docker`, `~/.netrc`, `~/.password-store` and `~/.config/gcloud`. Rule (e) checks that the deepest existing part of the path is on the root file system. Rules (a) and (d) compare names with case folded, as the default case-insensitive APFS volume does; rule (c) stays case-sensitive, so a mismatch can only reject. | SAF-007 (c) says the root belongs to the tool or sub-tool, and the registry that knows them arrives in M1-T06.
